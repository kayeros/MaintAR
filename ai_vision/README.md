# Роль 2. ИИ и компьютерное зрение: сервис `/analyze`

Принимает фото агрегата и возвращает видимые дефекты и узлы с рамками в формате общего контракта из `TEAM_TASKS.md`.

```
фото → уменьшение до 1280 px → мультимодальная модель (prompt.txt)
     → разбор JSON → проверка (класс из списка, рамка в кадре, confidence ≥ 0,4)
     → название, статус, узел, рекомендация → кэш → ответ
```

Если модель или сеть отказали, ответ всё равно будет: сначала демо-кэш (7 показательных фото), затем офлайн-детектор ржавчины на классическом CV, затем пустой ответ с полем `error`.

## Быстрый старт

```bash
cd ai-vision
pip install -r requirements.txt      # можно пропустить: без FastAPI поднимется встроенный сервер
python -m unittest test_vision -v    # 17 тестов, сеть не нужна

# выбрать модель (одно из трёх):
export ANTHROPIC_API_KEY=sk-ant-...                                  # Claude
export VISION_PROVIDER=openai VISION_BASE_URL=https://openrouter.ai/api/v1 \
       VISION_API_KEY=sk-or-... VISION_MODEL=qwen/qwen2.5-vl-72b-instruct  # OpenRouter
export VISION_PROVIDER=openai VISION_BASE_URL=http://localhost:11434/v1 \
       VISION_MODEL=qwen2.5vl:7b VISION_BOX_UNITS=pixel             # локально через Ollama

python server.py                     # http://<IP ноутбука>:8001
```

На Windows вместо `export` используйте `set` (cmd) или `$env:ИМЯ="значение"` (PowerShell).

Без ключа сервис работает в офлайн-режиме: для 7 показательных фото отдаёт эталон из демо-кэша, на остальных находит только ржавчину (`surface_corrosion`).

Из России прямые API Anthropic и OpenAI без обхода недоступны. Рабочие варианты: OpenRouter (оплата картой может не пройти) или локальная модель через Ollama (`ollama pull qwen2.5vl:7b`, нужно около 6 ГБ видеопамяти или терпение на CPU). Локальная модель заодно страхует демо от отказа сети.

## API

| Метод | Что делает |
|---|---|
| `POST /analyze` | multipart: `photo` (файл), `unit_id` |
| `POST /analyze_json` | JSON: `{"image_base64": "...", "unit_id": "CN-1"}` |
| `GET /classes` | справочник классов, узлов, статусов |
| `GET /health` | текущий провайдер и модель |

Параметры запроса у обоих `analyze`: `?provider=anthropic|openai|offline`, `?nocache=1`.

Ответ (поля контракта плюс дополнительные, которые можно не читать):

```json
{
  "equipment": "центробежный насос, узел уплотнения вала",
  "findings": [{
    "cls": "shaft_seal_leak", "confidence": 0.9, "box": [0.43, 0.30, 0.17, 0.66],
    "explanation": "Капли и потёки масла стекают из-под крышки уплотнения вниз по корпусу.",
    "name": "Течь торцевого уплотнения вала", "status": "defect", "comp": "seal",
    "recommendation": "Оценить интенсивность течи по паспортной норме..."
  }],
  "nodes": [{"comp": "seal", "name": "уплотнение вала", "box": [0.39, 0.25, 0.23, 0.42]}],
  "status": "defect",
  "status_text": "признаки возможного дефекта",
  "disclaimer": "Предварительный осмотр. Отсутствие видимых дефектов не подтверждает исправность",
  "source": "model",
  "model": "claude-sonnet-5-5",
  "ms": 4210,
  "unit_id": "CN-1"
}
```

- `source`: `model` (свежий ответ модели), `cache` (повтор того же файла), `demo_cache` (запасной эталон), `cv_offline` (без нейросети), `error`.
- `status` общий по фото: худший из статусов находок, `ok` если находок нет. `ok` означает «видимых проблем не обнаружено», а не «исправно».
- `error` и `warning` появляются, если модель не ответила и сработал запасной путь.
- `dropped` (если есть): что отброшено проверкой и почему. Полезно для отладки промта.

### Пример для роли 1 (React Native)

```js
const form = new FormData();
form.append('photo', { uri: photo.uri, name: 'photo.jpg', type: 'image/jpeg' });

// рамка: left = box[0]*W, top = box[1]*H, width = box[2]*W, height = box[3]*H
```

### Для роли 3 (встроить в общий бэкенд на :8000)

```python
from vision import analyze_image          # папка ai-vision в PYTHONPATH
@app.post("/analyze")
async def analyze(photo: UploadFile = File(...), unit_id: str = Form(None)):
    return analyze_image(await photo.read(), unit_id)
```

Классы берутся из `../pump-diagnostics/rules.json` (раздел `visual_rules`, поле `class`), если файл есть, иначе из `classes.json`. Путь можно задать в `RULES_PATH`.

## Обученный детектор YOLO (дополняет модель)

Для 9 классов, под которые нашлись открытые данные, обучен детектор YOLOv8s:
`surface_corrosion`, `pipe_leak_pitting`, `pipe_crack`, `shaft_seal_leak`, `stem_packing_leak`,
`seal_overheat`, `salt_deposits`, `frame_corrosion_loose_bolts`, `cable_insulation_damage`.
Остальные 9 классов остаются за мультимодальной моделью: открытых данных под них нет.

Подключение: положить веса в `models/pump_defects.pt` и поставить `pip install ultralytics`.
Дальше всё автоматически:

- с мультимодальной моделью находки детектора добавляются к её ответу; у каждой находки поле
  `by`: `model`, `detector` или `model+detector`, если обе нашли одно и то же;
- `VISION_PROVIDER=yolo` — только детектор, без сети и ключей;
- офлайн-режим берёт детектор вместо поиска ржавчины по цвету;
- `VISION_HYBRID=0` выключает детектор, `VISION_DETECTOR_CONF` задаёт порог (по умолчанию 0,35).

Переобучение (нужна видеокарта, удобно в Google Colab):

```bash
cd train
ROBOFLOW_API_KEY=... python build_dataset.py      # ~13 тыс. изображений из 28 наборов Roboflow
python train_yolo.py --model yolov8s.pt --epochs 30
```

`train/sources.py` — список наборов и правила перевода их классов в наши. Лицензии наборов
(CC BY 4.0, MIT) и авторы собираются в `ATTRIBUTION.md`, их нужно указать в презентации.

Оговорки по данным: `shaft_seal_leak` учится на общих снимках масляных подтёков, `salt_deposits` —
на высолах на кирпиче, `seal_overheat` — на любом дыме и паре, `frame_corrosion_loose_bolts` —
на ослабленных и ржавых болтах вообще. Метрики на открытых данных выше, чем будут на насосах;
честная оценка — `python eval.py --provider yolo` на фото кейса.

## Проверка качества

```bash
python eval.py --photos "../Кейс"            # 52 фото по photo_catalog.csv
python eval.py --photos "../Кейс" --clean    # без водяных знаков и дубликатов (43 фото)
```

Скрипт печатает и сохраняет в `eval_out/eval_summary.md` долю попаданий по фото и полноту по каждому классу. Эти цифры идут в презентацию. Демо-кэш при оценке выключен, ответы модели кэшируются, повторный прогон бесплатный.

Уже измерено, офлайн-детектор без нейросети (`--provider offline`): попадание по фото 24 из 52 (46 %), ржавчина находится на 15 из 17 фото, где она размечена, но и на 14 фото, где главным дефектом размечено другое. Остальные 16 классов офлайн-режим не распознаёт. Цифры для мультимодальной модели появятся после прогона с ключом.

## Демо

- `VISION_DEMO_MODE=1 python server.py`: для 7 показательных фото ответ сразу берётся из `demo_cache/demo.json`, без модели. Фото узнаётся по перцептивному хэшу, поэтому срабатывает и после пересжатия телефоном. Без этого флага демо-кэш включается только при отказе модели.
- Показательные фото: течь уплотнения вала, дым у сальника, сломанные рёбра ЭД, обгоревший клеммник с кабелями, ржавая рама, порванная теплоизоляция, побежалость на щите ЭД. Список в `make_demo_cache.py`.
- Рамки эталонов размечены вручную по фото. Это не вывод модели, на защите так и говорить.
- `python draw.py фото.jpg ответ.json out.jpg` рисует рамки поверх фото для слайдов.

## Что важно знать команде

Для роли 4 (данные и защита), по итогам разметки фото:

- `grounding_missing` и `indicator_mismatch`: в кейсе нет ни одного фото. `handwheel_damage`, `terminal_overheat`, `cable_insulation_damage`, `overheat_discoloration`, `seal_overheat`, `cooling_fins_damage`, `insulation_damage`: по одному фото. Для честной оценки нужно по 2+ фото на класс.
- 13 фото из 52 показывают внутренние дефекты (подшипник, кавитация колеса, обмотки, ротор). Камера снаружи их не увидит, в разметке они `none`: правильный ответ модели «видимых дефектов из списка нет».
- 8 фото сгенерированы нейросетью (водяной знак Qwen), в том числе 5 из 7 показательных. Жюри может это заметить. Лучше доснять реальные фото или прямо сказать на защите.
- 4 фото со стоковыми водяными знаками (alamy, shutterstock), 2 пары дубликатов и 1 почти дубликат. Пометки в колонке `flags`.
- Разметка 8, 17, 18, 22 спорная (помечено в `note`), её стоит проверить.

Ограничения сервиса:

- Анализ по фото предварительный: модель видит только внешние признаки.
- Рамки от языковых моделей приблизительные, точность локализации ниже, чем у обученного детектора.
- Офлайн-детектор путает ржавчину с деревом, кожей, бурой краской.
- Тексты рекомендаций составлены по общей практике, их должен проверить технолог.
